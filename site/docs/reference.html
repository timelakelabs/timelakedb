Line Protocol

The write format is InfluxDB line protocol, one record per line. Every rule below is what the parser in crates/ingest actually does, not what the format specifies in general.

Grammar 
measurement[,tag_key=tag_value...] field_key=field_value[,field_key=field_value...] [timestamp]
# └ table         └ dictionary columns   └ typed columns              └ integer, precision-scaled

Parsing

  • Records are separated by \n; a trailing \r is stripped, so CRLF bodies are accepted.
  • Blank lines are skipped, and a line beginning with # is a comment.
  • A measurement with no field set is an error — tags alone are not a record.
  • The batch is atomic: if any line fails to parse the whole request is rejected with 400 and nothing in it is written.

Escaping

PositionEscapes honoured
Measurement, tag key, tag value, field key\,   \=   \\   and a backslash before a space
Quoted string field value\" \\ — a backslash takes the next character literally

A backslash before anything else is kept as a literal backslash. esc,path=a\,b\ c v=1 stores the tag value a,b c.

Field types

Written asTypeColumn
1.5, -1.5e3, 2E-2floatFloat64
42isigned integerInt64
42uunsigned integerUInt64
t T true True TRUE / f F false False FALSEbooleanBoolean
"quoted text"stringUtf8

Tags are always strings and always become Dictionary<Int32, Utf8> columns — that is the whole high-cardinality argument: a tag costs what a compressed column costs. Full-width values round-trip exactly, including 9223372036854775807i and 18446744073709551615u.

Timestamps

  • An integer in the unit given by the precision parameter: ns (or n, the default), us (or u), ms, s. Any other value is a 400.
  • Omit it and the server's clock is used — which is what Telegraf does by default.
  • The column is Timestamp(Nanosecond, "+00:00"), never null. Timestamps slightly in the future are legitimate and are stored as given.

Schema rules

  • The first write of a field name fixes its type. Integers and unsigned integers are accepted into an existing float column (widening); nothing else is coerced.
  • A conflicting type is a 400 naming the field, and the whole request is rejected: field 'v' type conflict: column was created with a different type than Str("oops").
  • New tags and fields may appear at any time; earlier rows read back as null for them.
  • A key repeated inside one line takes its last value, for both tags and fields.
  • An empty tag value (h=) is stored as an empty string. InfluxDB drops such a tag instead — one of the few places the behaviour differs.
  • The primary key is the tag set plus the timestamp. Duplicates are de-duplicated last-write-wins at flush, and again across files during compaction.

Text encoding

  • Bodies must be UTF-8. Measurement names, tag keys and values, field keys and string field values all round-trip exactly — München reads back as München.
  • There is no byte or code-point escape in line protocol, so a non-UTF-8 byte cannot be expressed. A body containing one is refused whole with {"error":"body is not utf-8"}, before the parser and before the WAL — nothing partial is written. A client holding Latin-1 or binary data must transcode it, or carry it base64-encoded in a string field.
  • Valid UTF-8 that is merely unusual — tabs, NUL, combining marks, bidirectional overrides — is stored verbatim and returned verbatim. The only characters the format itself reserves are the delimiters, and those are what the escapes above are for.

Write errors

Errors are JSON, and the message identifies the offending line by its 1-based position in the request body:

400 responses 
{"error":"line 2: bad float \"notanumber\" in \"probe,h=a v=notanumber\""}
{"error":"line 1: no field set in \"probe,h=a\""}
{"error":"line 1: tag 'h' has no value in \"probe,h v=1\""}
{"error":"line 1: bad timestamp \"abc\" in \"probe,h=a v=1 abc\""}
{"error":"bad precision \"bogus\""}
{"error":"missing 'db' parameter"}

SQL Dialect

Queries run on Apache DataFusion — its dialect, its function library, its error messages. Each query gets a fresh session containing the tables of exactly one database, so nothing a query defines outlives it.

Schema seen by a query

ColumnTypeNull
timeTimestamp(Nanosecond, "+00:00")never
each tagDictionary(Int32, Utf8)yes — null where the tag was absent
each fieldFloat64 / Int64 / UInt64 / Boolean / Utf8yes

One table per measurement. DESCRIBE <table> works and is the reliable way to inspect a schema.

What works

Verified against a running server: joins, common table expressions, window functions, COUNT(DISTINCT …), date_trunc, date_bin, now(), INTERVAL arithmetic, AT TIME ZONE, EXPLAIN and DESCRIBE.

What does not

The data-plane SQL surface is read-only, enforced on the logical plan: anything that would write a file, change the catalog, or modify data is refused before it runs.

StatementBehaviour
SHOW TABLES, information_schemaSupported. The default catalog is named after the database, so poc.public.events resolves and matches what Flight SQL reports
INSERT, UPDATE, DELETERefused — the surface is read-only (write with line protocol; data leaves only by retention, FR-7)
CREATE TABLE, DROP TABLERefused — the read-only guard rejects DDL before it plans, so a DROP TABLE no longer appears to succeed while doing nothing
COPY … TO '<path>'Refused — this once wrote a file as the server process; the surface is now read-only, enforced on the plan (even inside EXPLAIN ANALYZE). See Security

JSON encoding of results

/api/sql returns an array of row objects:

Types on the wire 
[{"b":true,"f":1.5,"host":"alpha","i":42,"s":"hi there",
  "time":"2025-08-07T20:53:20Z","u":7}]
  • Int64, UInt64 and Float64 are JSON numbers — full 64-bit range, not stringified.
  • Boolean is true/false.
  • Timestamps are RFC 3339 strings in UTC; dictionary (tag) values and strings are strings.
  • SQL NULL is JSON null.

Query errors

400 responses 
{"error":"Error during planning: table 'poc.public.nope' not found"}
{"error":"database 'nosuch' does not exist (write to it first)"}
{"error":"query timed out after 600s (server-side cap, RR-2)"}

A database exists once something has been written to it; querying an unknown one is an error rather than an empty result. Planning errors are returned verbatim, which discloses table and column names to any caller.

Admin authentication (SEC-4)

Every /admin/* route requires a session. The data plane (writes, /api/sql, Flight SQL) authenticates separately by token when enabled — see Data-plane tokens below; /metrics always takes none. Sign in at POST /admin/session to receive an HttpOnly, SameSite=Strict cookie and a CSRF token that every cookie-authenticated mutation must echo in X-TimeLake-CSRF; automation may instead send Authorization: Bearer <session>, which is exempt from CSRF. Sessions expire after 30 minutes idle or 12 hours absolute, and repeated failures back off per principal.

First run seeds admin/admin. That credential can do exactly one thing — POST /admin/password — and every other admin route answers 403 password_change_required until it does. Changing it invalidates all of that principal's sessions, so you sign in again. The new password must be at least 8 characters and cannot be the username or admin. Set TIMELAKE_ADMIN_BOOTSTRAP_PASSWORD to provision a real password instead, and alert on timelake_admin_default_credential_active.

Roles are ordered: viewer reads, operator makes non-destructive changes including growing a retention window, and admin covers the destructive direction — shrinking, introducing, or removing a window — plus TLS reload.

Admin console (/admin/ui)

GET /admin/ui serves the management page: one self-contained HTML document compiled into the binary — no build step, no external assets, no separate service to deploy or expose. The page itself loads without a session; everything it can do requires one, so an unauthenticated visitor sees a sign-in form and nothing else.

The flow is sign in → rotate if required → manage. On a first run the seeded admin/admin credential is quarantined, so the console goes straight to a forced password change and returns to sign-in afterwards (rotation ends every session for that principal, including the current one). After that it manages per-table retention: the active policies, a set/remove form with table-name completion from SHOW TABLES, the live timelake_retention_drops_total counter, and a standing warning that shrinking a window deletes data on the next enforcement pass — permanently once TIMELAKE_GC_GRACE_SECS elapses. The header shows who you are and your role, and the page states which role each action needs; the server is what enforces it, so an action above your role fails with 403 rather than being hidden. A banner appears while the seeded credential is still active.

The console is on the data port. It answers on 1963 alongside writes and /api/sql, so publishing the write API publishes the console's front door — the session is what protects it, not the network boundary. Binding privately (TIMELAKE_ADDR=127.0.0.1:1963) is still the primary control, and a reverse proxy must forward cookies and the X-TimeLake-CSRF header. A dedicated admin listener on 1965, bound to loopback by default and carrying /admin/* away from 1963, is designed as phase U0 in docs/CONSOLE.md — not shipped.

Row visibility labels (SEC-2)

A tag named _visibility holds an Accumulo-style label expression per row — admin, ops&audit, (ops&audit)|admin, quoted tokens ("needs quoting") — written as an ordinary tag, no special endpoint. Queries see only rows whose expression their session's authorizations satisfy, supplied via the X-TimeLake-Authorizations header (comma-separated), the /api/sql body field authorizations, or x-timelake-authorizations gRPC metadata on Flight SQL. Rows without a label are visible to everyone; a malformed expression is visible to no one (fail closed); & and | may not mix without parentheses. Enforcement happens inside the scan, so aggregates cannot count hidden rows. On the anonymous path, authorizations are claims, not credentials — the SEC-4 sessions that guard /admin/* do not apply to /api/sql or Flight SQL. A client certificate changes that for the caller that presents one; see below. Presenting one is optional, so the honor-system front door remains for anyone who declines. See SECURITY.md.

Client certificates (SEC-3 v2, want mode)

Set TIMELAKE_TLS_CLIENT_CA to a PEM bundle of trust anchors and both listeners request a client certificate. A client that presents one has its chain verified and its subject common name read as an identity; a client that presents nothing is still served, unchanged. This is want mode, not required mode — stock Grafana and Telegraf hold no client certificate and must keep working, so requiring one would be a flag day.

A verified identity is what turns a SEC-2 claim into an authorization: the session's claimed authorizations are intersected with what that identity is granted, so authenticating can only narrow what a caller sees, never widen it. An identity with no grant policy recorded keeps its claims — no policy is not deny all, or presenting a certificate would break a working client. Identity currently reaches the query session over Flight SQL; /api/sql does not carry it yet.

Anchors hot-rotate on the same triggers as the serving certificate (file watch, POST /admin/tls/reload) with the same validate-before-swap rule, and the bundle may carry two CAs at once so client and server CAs roll independently. A bundle that will not parse leaves the last-good anchors serving and raises the alarm; an empty bundle is refused rather than silently trusting nothing.

Want mode is not by itself an access control. An attacker declines to present a certificate and takes the anonymous path. Its value is that authenticated callers can be held to less. Watch timelake_flight_connections_authenticated_total against timelake_flight_connections_anonymous_total to know when a deployment has migrated far enough to restrict the anonymous path — that decision should rest on a measurement, not a guess.

Data-plane tokens (SEC-4 phased)

TIMELAKE_DATA_AUTH controls whether the data plane authenticates: off (default — the Authorization header is not examined, so existing clients are untouched), optional (anonymous callers still served, but a presented token that does not verify is refused), and required (no valid token, no access, on both :1963 and :1964). The three states are a migration: stage from off to required while watching the request split, rather than flipping blind.

Tokens are issued from the console (POST /admin/tokens, admin only) and shown once — only a SHA-256 digest is stored. A client presents one on the Authorization header, and TimeLakeDB accepts three spellings so every stock client works unmodified:

HeaderClient
Bearer <token>Grafana (Flight SQL token field), Tributary
Token <token>Telegraf influxdb_v2 output
Basic base64(any:<token>)Telegraf influxdb (v1) output — token as the password

Each token carries a scope (read, write, or read_write — a shipping agent can be given write alone, so a leaked shipper credential cannot read the database back), an optional database allowlist, and optional SEC-2 grants that intersect the caller's claimed authorizations — so a token can only ever narrow what its holder sees. A token with no grants recorded leaves claims untouched (no policy is not deny-all). Revocation is immediate and a tombstone: the record stays so an operator can still see the credential existed.

A bearer token on a plaintext connection is a password in the clear. If you rely on data-plane auth over a network, enable TLS. And in required mode, timelake_data_requests_anonymous_total must stay at zero — any increase means something still reaches the data plane without a token.

Encryption at rest (SEC-1)

Set TIMELAKE_ENCRYPTION_KEY (64 hex characters) or TIMELAKE_ENCRYPTION_KEY_FILE and every object written to the store — Parquet data, catalog manifests, checkpoints — is envelope-encrypted: a fresh AES-256-GCM data key per object, wrapped by your key, in 64 KiB authenticated chunks so range reads (bloom probes, footer loads) stay cheap. A malformed key refuses to start. Objects written before the key was configured remain readable; the local WAL is not encrypted. Wrong key or tampered object is a clean named error, never silent data.

S3 object store + AWS KMS

TIMELAKE_OBJECT_STORE=s3://bucket/prefix moves every object to S3 (the WAL stays on local disk); AWS_ENDPOINT_URL points it at LocalStack for testing. TIMELAKE_KMS_KEY_ID (key id, ARN, or alias) switches the envelope's key source to AWS KMS data keys, cached by default — one data key per bounded window (TIMELAKE_KMS_CACHE_MAX_AGE_SECS, default 300; TIMELAKE_KMS_CACHE_MAX_USES, default 1000) and a decrypt-side cache, so thousands of objects cost a handful of KMS calls. TIMELAKE_KMS_CACHE=off restores strict per-object keys. Server-side, every PUT carries SSE-KMS with S3 Bucket Keys (TIMELAKE_S3_SSE_KEY_ID, defaulting to the KMS key id). Setting both TIMELAKE_KMS_KEY_ID and TIMELAKE_ENCRYPTION_KEY refuses to start.

Verified integrations

  • Telegraf, unmodified influxdb and influxdb_v2 output plugins, gzip on, token and organisation set to anything — the AT-6 fixture.
  • Grafana, stock InfluxDB datasource in SQL mode over Flight SQL on 1964; the provisioned dashboards in fixtures/grafana/ render unchanged.

Client libraries that only write line protocol over the endpoints above will work. Anything that calls a management, query or metadata API will not.

What to alert on

  • rate(timelake_flushes_total[15m]) == 0 while timelake_buffer_rows is high — maintenance is not draining the buffer, and the WAL will grow into backpressure.
  • timelake_wal_bytes approaching TIMELAKE_WAL_MAX_BYTES — writes are about to get 429s.
  • timelake_tls_last_reload_ok == 0 — a renewal was rejected and the node is serving on the last-good certificate.
  • timelake_tls_cert_expiry_seconds below two renewal periods.
  • timelake_tls_client_ca_last_reload_ok == 0 — a client CA bundle was rejected. Nothing is broken yet, because the last-good anchors keep verifying, which is exactly why it can go unnoticed until the anchors themselves expire and every client-certificate handshake starts failing at once.
  • timelake_data_requests_anonymous_total increasing while timelake_data_auth_mode == 2 (required) — something is reaching the data plane without a token; it must stay flat at zero.
  • timelake_parquet_files climbing without compaction — check for maintenance stage failed in the logs.
  • timelake_admin_default_credential_active == 1 — the well-known first-run password still works; anyone who reaches the admin port can take the admin role.
  • rate(timelake_admin_login_failures_total[5m]) climbing — someone is guessing; per-principal backoff is slowing them, not stopping them.

Logging is tracing to stdout, controlled by RUST_LOG (default info).
